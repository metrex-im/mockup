질환 칩 요약 + hoverbox칩 바에 질환을 전부 늘어놓을 공간이 없어 이름 1개 + 그외 n개로 줄였습니다. 이름으로 내보내는 것은 선택한 질환 중 질환 목록(가나다·ABC) 순서가 가장 앞선 것이고, n은 나머지 선택 개수입니다 — 선택한 순서와 무관하고, 주 질환 개념은 도입하지 않습니다(BE 추가 필드 없음). 그외 n개에 마우스를 올리면 선택한 질환 전체가 번호 매긴 목록으로 나옵니다(키보드 포커스에서도 열립니다). 1개만 선택했으면 그외 n개 칩 자체가 나오지 않습니다.
확인 필요 2건 — 이번 수정에서 새로 생긴 결정 지점
  1. 그외 n개 칩에 키가 필요합니다 — 녹음-진료기록-질환더보기-칩으로 가칭을 뒀습니다. GWT의 녹음-진료기록-질환-칩은 이제 앞선 1개만 가리키므로, “두 질환이 모두 표시된다”로 쓰인 2-17 · 3-19 · 3-20의 Then이 화면과 어긋납니다.
  2. hoverbox는 마우스 전용입니다 — 터치 환경에서 hover가 없습니다. 진료 녹음이 크롬 데스크톱 전용이라 현재는 문제없지만, 태블릿 사용이 생기면 탭 토글이 필요합니다.

코드를 확인한 결과 두 가지가 v4와 달랐습니다.
질환 선택 컴포넌트v4는 네이티브 <select multiple>로 그렸으나, admin-theme에는 이미 FormUiSelectMultiple이 있고 이는 네이티브 셀렉트가 아니라 체크박스 드롭다운입니다(SelectMultiple → SelectDropdown, 항목이 <li> + 체크박스). v5는 이 패턴으로 그렸습니다.
선택값 표시SelectCommon은 다중 선택 시 트리거에 displayText.join(', ')를 넣고 truncate합니다. 11개를 고르면 대부분 잘려서 안 보입니다 — 그래서 아래 칩 목록이 필수입니다(요청하신 그대로).
토큰임의 색·크기를 쓰지 않고 primary-500 #1467FF · mono-* · green-*, rounded-small .8rem, BoxButton 높이(M h-32 / XL h-46), font-size-13/14/16을 그대로 사용. rem base는 10px입니다.
문진 선택지 칩ClinicalSheetOptionChip 실제 클래스(rounded-8 border-1 px-12 py-6 font-size-13, 선택 시 bg-primary-500 text-white)를 그대로 재현.
다이얼로그 폭기존 VisitTypeSelectDialog는 width="w-400"(40rem)입니다. 질환 11개 + 선택 칩이 들어가면 좁아 w-480으로 넓혔습니다 — 확정 필요.
확인 필요 — 옵션별 data-testid는 컴포넌트 수정 없이 불가합니다 (코드로 확인)
SelectCommon.tsx의 SelectMultipleOptionInterface는 value · displayText · content · showCheckBox만 받고 data-testid 필드가 없습니다. SelectDropdown의 <li>에도 testid를 붙이는 경로가 없습니다. 따라서 GWT가 요구하는 옵션 키 11개(녹음-진료유형선택-질환-{질환}-옵션)는 현재 컴포넌트로 부여할 수 없습니다.
선택지는 둘입니다 — (a) OptionInterface에 dataTestId를 추가하고 DropdownElementItemWrapper의 <li>에 전달 (공용 컴포넌트 변경, 다른 화면에 영향 없음) / (b) 옵션 키를 폐기하고 셀렉트 키 하나로 GWT를 다시 쓰기. (a)를 권합니다 — (b)로 가면 1-2~1-12 · 2-1~2-11 Outline 22행의 {질환키} 열이 의미를 잃습니다.
남은 확인 3건
  1. Examples 표 행 번호 ≠ 화면 정렬 순서 — Confluence 질환 Examples 표는 노드 색인 순서(1~11행), 화면은 가나다·ABC입니다. 시나리오 3-21이 “(11행)”·“(10행)”으로 인용하는데 화면에서는 무릎 퇴행성 관절염이 4번째, 전방십자인대가 11번째입니다. “(목록 4번째)”·“(목록 11번째)”로 고치는 게 정확합니다.
  2. 문항 수 · 후처리 토큰 — “초진 · 11개”와 “재진 · 11개”를 눌러보시면 질환별 문진이 11세트(55문항)로 쌓입니다. 선행 티켓 ACLP-4461(토큰 최적화)과 부딪히는 지점입니다.
  3. 이 목업의 문항 수는 확정 스펙이 아닙니다 — 공통 8 + 질환 선택 1 = 9, 질환별 5로 그렸을 뿐입니다. QA 지적대로 티켓 배경은 21개, 스테이징 현재는 13개로 서로 다르고, 기존 13개가 공통 9 + 질환별 5로 어떻게 나뉘는지가 미정입니다(시나리오 5-2 판정 기준). 문항 수·매핑이 확정되면 목업 숫자와 3-1·3-2~3-12의 Then을 함께 고쳐야 합니다.
